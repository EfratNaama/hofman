## Collection Schemas

### 1. `activities`

Stores all activities available in the catalog. Supports filtering by category and day, keyword search, registration, and capacity checks.

| Field | Data Type | Required | Description |
|---|---|---|---|
| `_id` | ObjectId | Yes (auto) | Unique document identifier generated by MongoDB |
| `title` | String | Yes | Name of the activity |
| `description` | String | No | Detailed description of the activity; used in keyword search (FR-13) |
| `category` | String | Yes | Activity category for filtering |
| `dayOfWeek` | String | Yes | Day of the week the activity takes place |
| `activityDate` | Date | Yes | Specific calendar date; used for upcoming events and personal calendar filtering |
| `time` | String | Yes | Scheduled time of the activity |
| `maxParticipants` | Number | Yes | Maximum number of participants allowed (FR-11) |
| `currentParticipants` | Number | Yes | Current number of registered participants; incremented atomically on each registration |
| `availableSpots` | Number | Yes | Remaining available spots; decremented atomically with `currentParticipants` |
| `isActive` | Boolean | Yes | Whether the activity is visible in the public catalog |
| `requiresPayment` | Boolean | Yes | Whether the activity requires payment |
| `paymentLink` | String | No | URL to external payment system; no payment data is stored internally |
| `createdBy` | ObjectId | Yes | Reference to `administrators._id` who created the activity |
| `createdAt` | Date | Yes | Timestamp of creation |
| `updatedAt` | Date | Yes | Timestamp of last update |

---

### 2. `registrations`

Stores each participant registration for an activity. Registration records are created from the personal area using existing administrator-created profile data, or managed by administrators.

| Field | Data Type | Required | Description |
|---|---|---|---|
| `_id` | ObjectId | Yes (auto) | Unique document identifier generated by MongoDB |
| `activityId` | ObjectId | Yes | Reference to the registered `activities._id` |
| `activityTitle` | String | Yes | Snapshot of the activity title at time of registration |
| `identityNumber` | String | Yes | Identity number copied from the stored user profile at time of registration |
| `fullName` | String | Yes | Full name copied from the stored user profile |
| `phone` | String | Yes | Phone number copied from the stored user profile; used for duplicate prevention |
| `email` | String | Yes | Email copied from the stored user profile |
| `source` | String | No | Origin of registration: `"personal_area"` or `"admin_panel"` |
| `registeredAt` | Date | Yes | Timestamp of when the registration was created |

---

### 3. `user_profiles`

Stores the personal details of each participant. User profiles are created exclusively by authenticated administrators through the administration panel (FR-46). This collection is the source of truth for personal area access and registration without re-entering personal details.

| Field | Data Type | Required | Description |
|---|---|---|---|
| `_id` | ObjectId | Yes (auto) | Unique document identifier generated by MongoDB |
| `phone` | String | Yes | Phone number of the participant; unique identifier for the profile |
| `identityNumber` | String | Yes | Identity number entered by an administrator when creating the profile |
| `fullName` | String | Yes | Full name entered by an administrator when creating the profile |
| `email` | String | Yes | Email address entered by an administrator when creating the profile |
| `createdBy` | ObjectId | Yes | Reference to `administrators._id` who created the profile |
| `createdAt` | Date | Yes | Timestamp of profile creation |
| `updatedAt` | Date | Yes | Timestamp of most recent update |

> **Note:** The `user_profiles` collection is not a password-based account system. It is used to grant personal area access by exact full name + phone match, and to reuse stored details when registering from the personal area.

## Indexes

### `activities` Collection

| Index | Fields | Type | Purpose |
|---|---|---|---|
| `idx_activities_category` | `{ category: 1 }` | Single field | Supports category filtering |
| `idx_activities_day` | `{ dayOfWeek: 1 }` | Single field | Supports day filtering |
| `idx_activities_active_cat_day` | `{ isActive: 1, category: 1, dayOfWeek: 1 }` | Compound | Supports common catalog filtering |
| `idx_activities_availableSpots` | `{ isActive: 1, availableSpots: 1 }` | Compound | Supports available-capacity checks |
| `idx_activities_text_search` | `{ title: "text", description: "text" }` | Text | Enables keyword search |
| `idx_activities_activityDate` | `{ activityDate: 1 }` | Single field | Supports upcoming event and calendar sorting |

### `registrations` Collection

| Index | Fields | Type | Purpose |
|---|---|---|---|
| `idx_registrations_unique` | `{ phone: 1, activityId: 1 }` | Compound Unique | Prevents duplicate registrations for the same phone number and activity |
| `idx_registrations_activityId` | `{ activityId: 1 }` | Single field | Retrieves registrations for a specific activity |
| `idx_registrations_registeredAt` | `{ registeredAt: -1 }` | Single field | Supports admin sorting by registration date |
| `idx_registrations_personal_area` | `{ fullName: 1, phone: 1 }` | Compound | Supports calendar lookup for a recognized participant |

### `user_profiles` Collection

| Index | Fields | Type | Purpose |
|---|---|---|---|
| `idx_user_profiles_phone` | `{ phone: 1 }` | Single field Unique | Enforces one profile per phone number |
| `idx_user_profiles_fullName_phone` | `{ fullName: 1, phone: 1 }` | Compound | Supports personal area access by exact full name and phone |

### Other Collections

| Collection | Index | Fields | Purpose |
|---|---|---|---|
| `announcements` | `idx_announcements_publishedAt` | `{ publishedAt: -1 }` | Sort announcements newest first |
| `gallery` | `idx_gallery_uploadedAt` | `{ uploadedAt: -1 }` | Sort gallery images by upload date |
| `contacts` | `idx_contacts_submittedAt` | `{ submittedAt: -1 }` | Sort contact submissions |
| `contacts` | `idx_contacts_isRead` | `{ isRead: 1 }` | Filter unread submissions |
| `administrators` | `idx_administrators_username` | `{ username: 1 }` | Enforce unique admin usernames |

## Relationships Between Collections

```
administrators
   │
   │  Create and manage user profiles
   ▼
user_profiles
   │
   │  Exact fullName + phone lookup grants personal area access
   │  Stored profile data is reused for registration
   ▼
registrations
   ▲
   │  registrations.activityId → activities._id
   │
activities

activities.createdBy → administrators._id
announcements.createdBy → administrators._id
gallery.uploadedBy → administrators._id
center_info.updatedBy → administrators._id
activities.paymentLink → External Payment System URL
```

### Summary Table

| Relationship | Type | How Implemented |
|---|---|---|
| Administrator → User Profiles | One-to-Many | Administrators create, edit and delete `user_profiles` |
| User Profile → Personal Area | Lookup | Application queries `user_profiles` by exact `{ fullName, phone }` |
| User Profile → Registrations | Profile reuse | Personal area registration copies identity number, full name, phone and email from `user_profiles` into `registrations` |
| Activity → Registrations | One-to-Many | `registrations.activityId` references `activities._id` |
| Administrator → Activities | One-to-Many | `activities.createdBy` references `administrators._id` |
| Activity → Payment Link | One-to-One optional | `activities.paymentLink` stores an external URL only; no payment data is retained |
